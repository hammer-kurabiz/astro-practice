# 第1クール課題：AstroでコーポレートサイトのTOPページを制作・公開する

対象期間：2026年11月〜2027年1月 ／ 配布日：2026年11月25日

## 課題の目的

Astro・TypeScriptで固定ページを作り、ビルドしてWeb上に公開するところまで経験します。架空の金属部品加工会社「東和精工株式会社」のTOPページを制作してください。デザインを考える時間を抑え、Astroの構成、コンポーネント、データの扱い方、公開手順を学ぶ課題です。

このフォルダは課題資料です。Astroの完成コードやスターターは含めていません。

## 配布物

| ファイル | 用途 |
| --- | --- |
| `README.md` | 課題内容・提出物・完了条件 |
| `design/index.html` | ブラウザで開けるレスポンシブのデザイン見本。原稿もこのページを使用 |
| `design/assets/` | 支給写真と出典・利用条件の案内 |
| `design/SPEC.md` | 配色・余白・画面構成・リンクの仕様 |
| `REVIEW.md` | 提出時とレビュー時のチェックシート・MTG進行案 |

まず `design/index.html` をブラウザで開き、ウィンドウ幅を変えてPCとスマートフォンの表示を確認してください。インストールは不要です。HTMLは見本として参照できますが、提出物は別途Astroで構成してください。

## 制作するもの

TOPページ1ページ（`/`）を制作します。セクションの順番・文章・配色は見本に合わせてください。写真は `design/assets/machining.jpg` と `design/assets/lathe.jpg` を使用してください。素材探しやWebフォントの導入は不要です。余白や文字サイズの数px単位の差は問いません。

1. ヘッダー：文字ロゴ、和文の会社名、ページ内ナビゲーション
2. メインビジュアル：大きなキャッチコピー、背景の支給写真と下部の本文
3. お知らせ：ヒーロー内の右下に1件ずつ表示。固定データ3件を自動・手動で切り替える。詳細ページやCMSは不要
4. 事業内容：3つの加工サービスと主な対応材質
5. 私たちについて：会社紹介、支給写真、会社情報
6. 加工のご相談：問い合わせ時に必要な情報、受付時間、メールリンク
7. フッター：会社名、ページ内メニュー、架空企業の注記、コピーライト

想定する依頼は「法人顧客に対応加工と会社の概要を伝え、図面を添えた問い合わせにつなげたい」というものです。訪問者は設計・生産担当者を想定します。事業内容、材質、相談に必要な情報を読み取りやすく配置してください。会社の設定や設備情報は課題用の架空データです。

## 必須要件

- AstroとTypeScriptを使い、静的サイトとして出力する。
- 共通のHTML枠組み（`html`、`head`、`body`）をLayoutに分離する。
- ヘッダー・フッター・サービス項目を、それぞれAstroコンポーネントに分離する。サービス項目のPropsには型を付ける。
- サービス3件とお知らせ3件は、それぞれ型付きの配列から繰り返し描画する。データは別の `.ts` ファイルにまとめる。
- PCではサービス3列、スマートフォンでは1列にする。320px・390px・768px・1440pxの画面幅で横スクロールや重なりを出さない。
- ヘッダーを上部に追従させ、リンクのホバーには下線を使わず色の変化などを付ける。ページ内リンクの移動先がヘッダーに隠れないようにする。
- ナビゲーションとボタンは、指定のセクションまたはメールリンクへ移動できるようにする。
- `lang="ja"`、ページ固有の `title`、`description`、viewportを設定する。h1は1つにし、見出しを順序立てる。
- 支給写真をローカルアセットとして配置し、会社案内写真には適切なalt属性を付ける。ヒーロー写真は装飾背景として扱う。PC・スマートフォンでトリミングを調整する。
- キーボードでリンクを操作でき、フォーカス位置が分かるようにする。
- お知らせはヒーロー内に1件ずつ表示し、5秒間隔の切り替えと矢印アイコンによる前後移動を実装する。見本のスクリプトを参考にできる。
- ビルドと型チェックを通し、共有可能なURLへ公開する。

見出しの大きさ、濃紺・ブルーグレー・淡いブルーのセクション構成、写真のトリミングを意識してください。見た目はモダンですが、レイアウトはGridとFlexboxで実装できます。スクロールに応じたヘッダー背景の切り替えには、見本の短いスクリプトを参考にできます。複雑なアニメーションは不要です。

CSSの書き方は自由です。React等の追加UIフレームワークは使わず、AstroとCSSを中心に実装してください。

## 今回の対象外

microCMS連携、ニュース詳細、フォーム送信、検索、ページネーション、アニメーション、アクセス解析は不要です。OGP画像や構造化データなどの拡張は第3クールで検討します。スマートフォンのヘッダーナビゲーションはハンバーガーメニューで開閉し、フッターメニューは常時表示してください。

## 進め方の例

学習を含む想定工数は8〜12時間です。Astro未経験の場合は追加時間を見込み、時間を超えそうな場合は詰まった点を共有してください。提出日はMTGで決めます（第1クールの終了は2027年1月31日）。

| 手順 | 目安 | 到達点 |
| --- | --- | --- |
| 環境構築・最小ページの公開 | 1〜2時間 | AstroのページがURLで表示できる |
| 構造・コンポーネント・データ | 2〜3時間 | 全セクションと固定データが表示できる |
| CSS・レスポンシブ | 3〜4時間 | PC・スマートフォンで読める |
| 検証・再公開・README作成 | 2〜3時間 | 他のメンバーが起動・更新・公開できる |

空のプロジェクトから始めます。例えば `npm create astro@latest` で作成し、最小構成のテンプレートを選んでください。Node.jsの要件は作業時の[公式セットアップガイド](https://docs.astro.build/en/install-and-setup/)で確認し、実際に使用したNode.js・Astro・パッケージマネージャーのバージョンを記録します。作成したプロジェクトのlockfileも提出してください。

型チェックには `astro check` を使用してください。`astro build` 単独では型チェックを行わないため、必要な依存関係とスクリプトは[公式TypeScriptガイド](https://docs.astro.build/en/guides/typescript/)を参考に設定します。公開先はチームで利用できる静的ホスティングを1つ選び、使用したサービス名と公開手順を残してください。

推奨構成の例です。ファイル名や分割粒度は調整できます。

```text
src/
  layouts/BaseLayout.astro
  components/Header.astro
  components/Footer.astro
  components/ServiceCard.astro
  data/services.ts
  data/news.ts
  pages/index.astro
  styles/global.css
```

## 提出物

- ソースコードのリポジトリURLと確認できる公開URL
- PC（1440px）・スマートフォン（390px）のスクリーンショット
- 提出用README：使用バージョン、インストール・起動・型チェック・ビルド・公開の手順、お知らせ1件の追加方法
- 工夫した点、詰まった点、その解決方法、残っている課題（あれば）
- `REVIEW.md` の自己チェック結果

認証情報やAPIキーをリポジトリに入れないでください。今回の課題にmicroCMSのAPIキーは必要ありません。

## 完了条件

`REVIEW.md` の必須項目をすべて満たし、レビュー担当者がREADMEの手順で起動・ビルドでき、公開URLでPC・スマートフォン表示を確認できれば完了です。お知らせを1件追加して再公開できることも確認します。デザインの完全な一致や任意の追加機能は合格条件にしません。
